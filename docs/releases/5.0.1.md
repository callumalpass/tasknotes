# TaskNotes 5.0.1

## Added

- Added **Show all properties on task cards** (Settings → Appearance & interaction → Task cards). On by default when no choice has been saved; previously saved choices are preserved. When it is on, properties that do not fit on a narrow card wrap onto extra lines instead of being hidden behind a count such as +3, as they did in 4.x. Task links in notes have a separate wrapping option, which is off by default. See [Appearance settings](https://tasknotes.dev/settings/appearance/).
  - Thanks to @dh-gh-1 for the suggestion ([#2583](https://github.com/callumalpass/tasknotes/discussions/2583))
- Added **Show all properties on inline task cards** (Settings → Appearance & interaction → Inline tasks). When it is on, a task link on its own line in a note lists every selected property on extra lines under its title, instead of hiding the ones that do not fit behind a count such as +3. It is off by default, so task links stay on one line, and links inside a sentence still show only the title. **Attachments** can now be chosen in **Inline task card properties** and **Default visible properties**, and appear as links named by their file. See [Inline tasks](https://tasknotes.dev/features/inline-tasks/).
  - Thanks to @dh-gh-1 for the suggestions ([#2595](https://github.com/callumalpass/tasknotes/discussions/2595), [#2597](https://github.com/callumalpass/tasknotes/discussions/2597))

## Fixed

- Fixed the calendar view picker sometimes displaying "3 days" after choosing Week in a narrow pane. It now keeps the Week selection while showing the compact three-day layout.
- (#2592) Fixed generated default `.base` files breaking when a field mapping uses a property name with a space, such as `due date`. Filters and formulas wrote the name bare (`due date.isEmpty()`), so views showed no tasks or formula errors. They now read such names as `note["due date"]`, for every mapped field. The All Tasks view also sorted by `due` instead of the mapped due property. Run **TaskNotes: Update default base files** to regenerate existing files; this overwrites manual edits in them. See [Default base templates](https://tasknotes.dev/views/default-base-templates/).
  - Thanks to @hughbiquitous for reporting
- (#2594) Fixed Obsidian freezing when a note showed a TaskNotes calendar in list (Agenda) layout inside a `base` code block. The agenda kept loading more days, and redrawing every task each time, until Obsidian stopped responding. A calendar in a code block now sizes to its content, as one embedded with `![[...]]` already did.
  - Thanks to @sovf4717 for reporting
- Fixed tags, contexts, projects and attachments in task links in notes stacking one per line or running together, such as "@studio@phone". They now sit in a row with a space between them, as on task cards in Bases views.
- Fixed task links in notes not updating after a change to **Inline task card properties** until the note was reopened.
- (#2598) Fixed task links on Markdown checkbox lines (`- [ ] [[Task]]`) in Live Preview showing a cut-down card that sat lower than the checkbox. They now show the same one-line card as in Reading view, with priority and dates. A task link alone in a bullet under a checkbox item also no longer leaves blank lines around it (see #2579).
  - Thanks to @TobyDallas for reporting
- Fixed calendar event titles being cut through the middle of a line in blocks of about an hour. Titles now show as many whole lines as fit above the time and end with an ellipsis, and blocks too short for both put the title and time on one row. This also follows Obsidian's font size setting.
- (#2559) When TaskNotes cannot read its settings file at startup, it now says so instead of failing with only Obsidian's "Failed to load" message. It still does not start, so your settings are not overwritten with defaults. The notice says that restarting Obsidian usually fixes this and that reinstalling TaskNotes deletes its settings. TaskNotes also now waits up to about two seconds for the file to become readable, since during a plugin update the previous version can still be saving it.
  - Thanks to @0x326-CHR for reporting
- Fixed tracked-time blocks in the calendar hiding the task title unless the block was very short. The title now appears beside the status icon, as it does on scheduled tasks.
- Fixed expanded subtasks of a task with no dates or properties being squeezed onto one line, with their dates and properties overlapping the title. Subtasks now keep their own layout.
- (#2579) Fixed task links on their own line in Live Preview taking up about three lines each, with blank space above and below the task and list bullets pushed onto a separate line. Each task now takes one line again, as it did in 4.x.
  - Thanks to @BrucePlumb for reporting
- (#2587) Fixed TaskNotes Bases views embedded in a note in the right sidebar keeping the note's side margins and scrolling separately from the note, a regression of #765. Embedded task lists in either sidebar again span its full width, in Reading view and now also in Live Preview.
  - Thanks to @TonyAtlas for reporting
- (#2581) Fixed task cards in Bases views showing "Normal" priority, with the Normal colour, for notes that have no priority property. These cards now show no priority, which matches how Bases sorts and filters the missing property and how the default priority formulas rank it (below every configured priority).
  - Thanks to @arthurhfcardoso for reporting
- (#2590) Fixed TaskNotes views embedded in Markdown table cells shrinking until each card showed only its status and priority icons, with no title. Embedded views now keep a readable minimum width (the table scrolls sideways when the note is too narrow), and titles stay left-aligned in centred columns.
  - Thanks to @DevOps-Toast for reporting

## Changed

- Task cards that show the attachments property now list each attachment as a link named by its file, such as *Quarterly report.pdf*, instead of its full vault path. Each name fits, collapses into the +N count, or wraps like any other property, and the paperclip count is no longer shown alongside the names. To show attachment names, add **attachments** to the view's properties. See [Appearance settings](https://tasknotes.dev/settings/appearance/).
  - Thanks to @dh-gh-1 for the suggestion ([#2584](https://github.com/callumalpass/tasknotes/discussions/2584))
- The two-pane task modal (Create with More fields, and Edit) now uses the window's available height, up to 900px, instead of a fixed 540px, so fields, attachments and details need less scrolling. It still keeps one height when More fields opens.
  - Thanks to @dh-gh-1 for the suggestion ([#2585](https://github.com/callumalpass/tasknotes/discussions/2585))
- (#2590) Task cards in Bases views that show priority now have a bar in the priority's colour along their left edge, so priority is visible at a glance and not only from the small mark at the end of the card. Tasks with no priority, or a priority of weight 0 such as *None*, have no bar. See [Appearance settings](https://tasknotes.dev/settings/appearance/).
  - Thanks to @kmaustral for reporting
