# TaskNotes 5.0.0-beta.7

> [!info] TaskNotes v5 beta
>
> This is an opt-in beta. TaskNotes 4.16.1 remains the recommended stable release.

## Before updating

- Requires Obsidian 1.13.1 or newer. Back up the complete vault and finish syncing before updating. See the [v4 to v5 upgrade guide](https://tasknotes.dev/migration-v4-to-v5/) for metadata upgrades and recovery. Avoid simultaneous metadata upgrades on other devices; TaskNotes App setup still requires its separate consent.
- This beta includes the new Calendar engine, Lingui interface translations and the collection-wide settings record described below. Existing Base files are not rewritten automatically.
- This beta includes the changes released in [4.15.0](https://github.com/callumalpass/tasknotes/releases/tag/4.15.0), [4.16.0](https://github.com/callumalpass/tasknotes/releases/tag/4.16.0) and [4.16.1](https://github.com/callumalpass/tasknotes/releases/tag/4.16.1), and brings the v5 line up to date with main after 4.16.1.
- Returning to beta.6 after the metadata upgrade is not a clean rollback. In native testing, task files were unchanged and locally saved settings remained available, but beta.6 could not initialize canonical settings and warned about the newer task schema. It does not read the new settings record. Restore the pre-upgrade backup rather than relying on a binary-only downgrade.

## Added

- (#1955) Added Italian interface translations, localized dates and count-aware messages in bundled builds and downloadable language packs. UI language and NLP language remain independent settings.
  - Thanks to @starise for contributing and reviewing the Italian translation.

- Added highlighting to the natural language input in the task creation dialog. Dates, recurrence, estimates, priority, status, tags, contexts, projects and custom fields are highlighted as you type, so you can see what will become the title. See [Highlighting in Natural Language Input](https://tasknotes.dev/features/task-management/#highlighting-in-natural-language-input).

- Added an opt-in build mode for downloadable interface language packs, with bundled English, validated local caching for offline use, and retry support. Ordinary builds continue bundling all supported languages. Versioned public hosting, a guarded operator publisher, and conditional-create publication tooling are available for experimental builds. Publication rejects permission errors even when identical objects already exist. See [Downloadable language packs](https://tasknotes.dev/development/language-packs/) for build configuration.

## Changed

- With the mdbase integration enabled, collection-wide app behaviour (natural-language triggers, task and occurrence templates, archive moves, stopping timers on completion, resetting checkboxes on recurrence, the frontmatter link format, and per-status next status, cycle exclusion and auto-archive) is now stored in the TaskNotes settings record, `_settings/dev.tasknotes.md`, which TaskNotes App also uses. The task type moves to the `tasknotes.task` 0.3.0-rc.6 contract, which no longer holds these settings. Upgrading a collection creates the record from your saved settings or the earlier task type in the same backed-up step; an existing record keeps its values and gains only missing ones. See [TaskNotes settings record](https://tasknotes.dev/migration-v4-to-v5/#tasknotes-settings-record).

- Preserved the ISO date display preference and preferred clock format alongside localized date labels in calendars, task cards and dialogs. Native settings retain translated default labels, count-aware reminder and sync summaries, and language-pack retry controls.
- Kept calendar month rows in the accessibility tree while adapting the calendar styles and hover/drag stacking to Obsidian.

- Use the published shared translation tooling instead of bundled development tarballs; all ten interface languages remain available offline in ordinary builds.

- Calendar view settings now use fewer, task-focused sections, with less common controls under Advanced and clearer names for time-grid and event limits. Saved `.base` settings keep applying unchanged. See [Calendar Views](https://tasknotes.dev/views/calendar-views/#view-options).

- The Calendar view now uses TaskNotes' own calendar engine instead of FullCalendar. Existing calendar view settings in `.base` files keep working, including the saved view, custom day count, first day of week, time format, slot range and size, height mode, week numbers, weekends, all-day row, today column width, and event limits.
  - Events update in place when tasks change, and changing a view setting no longer rebuilds the calendar.
  - Long-press drag on touch screens no longer competes with scrolling.
  - Calendar views now work in popout windows.
  - CSS snippets that target FullCalendar's internal classes (such as `.fc-timegrid-slot` or `.fc-daygrid-event`) no longer apply. TaskNotes' own event classes, such as `fc-task-event`, `fc-recurring-event`, `fc-timeblock-event`, `fc-ics-event` and the tag and project classes, are unchanged.

- Moved interface translations to Lingui catalogues with count-aware messages, locale-aware numbers and dates, and localized generated Bases labels. Ordinary builds retain all ten bundled interface languages.

- Kept stored default names and reminder descriptions in English, translating unchanged defaults only for display. Restored English `.ics` descriptions and kept persisted Google Calendar metadata in English so exports do not vary with the exporting device’s interface language; user-authored labels are preserved.

- Localized command notices, calendar connection and webhook settings, date/reminder/action/file/timeblock dialogs, task-property pickers, recurrence controls and statistics labels in all nine non-English interface languages. User-authored titles, paths, status labels and property names remain unchanged.

- Rebuilt natural language parsing on recognized spans. Titles keep only the task text: connector words go with the value they introduce ("call Jo at 3pm" gives "call Jo"), and separators and brackets left by a removed value are dropped.
  - Every NLP language now has fuller date, recurrence, estimate, status and priority phrases, including relative days, end-of-period dates, clock phrases, fortnightly and quarterly recurrence, `until` and `times` limits, and time ranges that set a scheduled time and an estimate.
  - A frequency word that names the task stays in the title and still sets the recurrence, as in "daily standup" or "reunión semanal". After an article, as in "buy a weekly planner", it is ordinary text.
  - Ambiguous single words such as French `fait`, Chinese `低` or `完成` no longer set a status or priority on their own; use the full phrase, such as `terminé`, `低优先级` or `已完成`.

- Reworked the task create and edit modals. Status, priority, dates, recurrence and reminders are now labelled chips that show their current value, replacing the icons with a dot. The edit modal starts with the title, **Task information** is collapsed, and **Archive** and **Delete** moved into a **More actions** (⋯) menu beside **Open note**. Empty field rows are more compact.
- Natural language input now updates the form as you type, so the **Fill form** button and the preview under the input were removed. Removing text from the input undoes what it set, and a field you changed by hand is no longer overwritten. See [Task Management](https://tasknotes.dev/features/task-management/).
- Closing the create modal with an unsaved draft now asks whether to save or discard it, as the edit modal does. **Open note** and **Archive** in the edit modal now ask before leaving unsaved changes, rather than afterwards.
- A missing title or invalid time estimate is now shown on the field itself instead of in a notice.
- (#2492) Clicking a recurring task's status indicator now follows the status cycle, as it does for other tasks, once the first completed status has a **Next status**. It moves the series through its open statuses, and reaching a completed status completes the occurrence shown on the card. Setups without that Next status keep completing the occurrence in one click, and dropping a recurring task on Done still completes it directly. In new setups, the built-in Done status now moves on to Open, so recurring tasks get this cycle, a finished series starts its next occurrence at Open, and clicking an ordinary task at Done moves it to Open instead of None. Saved statuses are not changed, but if your first completed status already has a Next status, recurring cards now take more than one click to complete. The task context menu still completes an occurrence directly. See [Recurring Tasks](https://tasknotes.dev/features/recurring-tasks/#completion-tracking).
  - Thanks to @Jomo94 for requesting this in #1370 and @martin-forge for the implementation
- Shortened the v5 and app announcement above the release notes, removed Android tester sign-up instructions, and refreshed the plugin beta link.
- (#2486) Collapsed Kanban columns now show the column's icon and title in the collapsed strip, with the title written vertically from top to bottom and long titles cut off. Previously the title was hidden, so collapsed columns could only be told apart by their colour. See [Collapsing Columns](https://tasknotes.dev/views/kanban-view/#collapsing-columns)
  - Thanks to @UniCode9696 for the suggestion

## Fixed

- The release-notes view now places the current version before earlier releases, including locally prepared beta builds.
- Kept recognition of generated 4.x mdbase metadata unchanged when integrating recurring-move fields, so existing collections can still upgrade safely.
- With the mdbase integration enabled, the first change to a setting stored in the TaskNotes settings record after upgrading a 4.x collection (for example turning off "Move archived tasks to folder" or changing the archive folder) is saved to `_settings/dev.tasknotes.md`. Previously it was kept only until Obsidian restarted.
- With the mdbase integration enabled, TaskNotes shows a notice naming any other `_settings/` file that also claims to be its settings record, such as a sync conflict copy of `_settings/dev.tasknotes.md`. It keeps using `_settings/dev.tasknotes.md` and leaves the other files unchanged. See [TaskNotes settings record](https://tasknotes.dev/migration-v4-to-v5/#tasknotes-settings-record).
- With "Use Markdown links in frontmatter" on, TaskNotes now writes Markdown links even when Obsidian's own "Use [[Wikilinks]]" preference is on. This covers the project picker, projects typed in the task modal's natural-language input, subtask and parent links, the parent-note project default and the Bases current-file default. Dependencies ("Blocked by") and projects added through inline task conversion do not follow this setting yet.
- A failed or interrupted mdbase metadata update now removes the files it created (contracts, schemas, the settings type and settings record) and its temporary `.tasknotes-stage-` files, as long as they still hold exactly what TaskNotes wrote. Edited files are kept.

Kept generated MDBASE schemas in stable English, and corrected literal template braces and missing values in task-created and unresolved-project messages.
