# TaskNotes 5.0.2

## Added

- (#2615) Added **Hide top-level subtasks** to the Calendar view's list (Agenda) layout and the month view's selected day panel, as in Task List and Kanban. When on, a subtask whose parent task is listed on the same day shows only under the parent's expanded subtasks instead of also as its own row. A subtask whose parent isn't listed that day keeps its own row. See [Agenda View](https://tasknotes.dev/views/agenda-view/#customization).
  - Thanks to @tistieom for the request
- (#2574) The task ID property can now be remapped like other task properties, under **Settings → TaskNotes → Properties → Metadata & integration properties → Task ID**. It defaults to `id`, so existing vaults are unchanged. When a collection's task type maps the ID to another property, TaskNotes uses that property. See [Task Properties](https://tasknotes.dev/settings/task-properties/#metadata-properties).
  - Thanks to @minchinweb for the request

## Changed

- (#2626) A Task List or Kanban view, or a Calendar in list mode, with no matching tasks now shows one short line, "No tasks match this view.", instead of a tall block with Filters and New buttons. Filter and New stay in the view's toolbar. This keeps notes with several embedded views, and the Relationship Widget, compact. A vault with no tasks at all still shows New and the Start Here guide.
  - Thanks to @prepare4robots for the suggestion
- (#2632) Recurring tasks now label their status control **Series status** in the task context menu, the status picker (including the **S** shortcut and the action palette), the edit modal's status button and the notice after a change. It sets the status of the whole series and records no occurrence; to complete one occurrence, use **Mark complete or skip**. Materialized occurrence notes keep **Status**. See [Completing Tasks](https://tasknotes.dev/features/task-management/#completing-tasks).
  - Thanks to @martin-forge for the suggestion
- (#2619) With Sign in with Google, up to ten calendars can now be shown at a time, up from five. **Calendars shown** states the limit when an account has more calendars than that, and the remaining toggles are disabled once the limit is reached, instead of turning on and switching back off. See [Calendar setup](https://tasknotes.dev/calendar-setup/).
  - Thanks to @Alireza-RS for the request
- (#2612) In Agenda views, the icon before each scheduled or due task (a calendar or flag, with the time for timed tasks) now opens a date picker for that date. Cards in Agenda leave out the date their row already sits under, so this restores one-click date changes. Recurring tasks still show their occurrence date on the card. See [Calendar views](https://tasknotes.dev/views/calendar-views/).
  - Thanks to @djagoo for the suggestion and @anrie for reporting (#2617)
- (#2608) A recurring task whose `COUNT` or `UNTIL` series has ended now counts as completed. Completing or skipping its last occurrence sets the task to your first completed status, and auto-archive applies to it as it does to other tasks in that status; reopening an occurrence reopens the task. Series without a limit are unchanged and still never auto-archived. An existing ended series is archived once you set it to an auto-archive status. See [Recurring Tasks](https://tasknotes.dev/features/recurring-tasks/#when-a-series-ends).
  - Thanks to @14790897 for the suggestion

## Fixed

- (#2667) Pressing Enter in task details now continues checklists, numbered lists, and bullet lists when creating or editing a task.
  - Thanks to @Xylemflo for reporting
- (#2622, #2640) Fixed the task dialog listing an attachment as "File not found", with no way to open it, after the attachment or its folder was renamed or moved. TaskNotes stores attachment links by full vault path, and when a file or folder is renamed Obsidian rewrites them in its own link format, such as `[[Quarterly report.pdf]]`. The dialog now finds those files the same way Obsidian and task cards do.
  - Thanks to @dh-gh-1 for reporting and @adityajai119 for diagnosing the cause
- (#2630) Fixed Task List rows from 640 px wide, where each task is on one line, cutting off the start of the scheduled date and squeezing or hiding properties. With **Show all properties on task cards** on, a project shrank to nothing and broke after every letter, making the row very tall; it now wraps between words and the title gives up some width instead. With the setting off, the +N count for hidden properties was itself cut off, and widening the list didn't bring the hidden properties back. The count now stays visible, and the properties come back when there is room.
  - Thanks to @martin-forge for reporting
- (#2631) Fixed dragging a later occurrence of a recurring task (dashed border) to another day in the calendar. The drop kept the occurrence on its original day, sometimes changed the time or removed the time from the recurrence rule for every later occurrence, and showed a notice saying the occurrence had moved. A drop on another day, or between the all-day row and a time slot, now moves only that occurrence by creating its occurrence note, and leaves the recurrence rule unchanged. A drop at another time on the same day still changes the series' time, and the notice now says so. A drop at the same day and time changes nothing. See [Calendar Views](https://tasknotes.dev/views/calendar-views/#drag-and-drop-behavior).
  - Thanks to @martin-forge for reporting
- (#2628) Fixed the scheduled date, due date, priority and other property pickers on phones and tablets opening the keyboard straight away, and running behind the keyboard so the lower options couldn't be reached. On mobile, these pickers now open as a bottom sheet again, and the keyboard opens only when you tap the search field. The sheet stays above the keyboard, and its list scrolls to every option.
  - Thanks to @prepare4robots for reporting
- (#2604) Fixed the task card in a narrow Pomodoro view (about 350 px wide or less) running the title under the status and priority icons. On narrow task cards in any view, the due-date icon could also sit on its own line above the date. It now stays beside the date. Turn on **Show all properties on task cards** to show time estimate and time tracked on extra lines instead of in a count such as +2.
  - Thanks to @RumiaKitinari for reporting
- (#2613) Fixed status and priority icons not lining up with the task title. In a wide Task List the priority icon sat slightly higher than the title, and when a title wrapped onto several lines with nothing below it, both icons sat between its lines. They now line up with the first line of the title in Task List, Kanban, Agenda and Pomodoro views.
  - Thanks to @wivi-prod for reporting
- (#2612) Fixed timed tasks in Agenda views with no other properties on the card not showing their time.
- (#2608) Fixed recurring tasks recording completions and skips on dates outside their rule. After a `COUNT` or `UNTIL` series had ended, **Completed today**, **Completed on (pick date)** and the edit modal's completion calendar could add dates past the end of the series to `complete_instances`. TaskNotes now records completions only against the series' own dates; actions with no occurrence to update are shown disabled or explain why, and dates already recorded can still be cleared. Completion-anchored series still accept any date. See [Recurring Tasks](https://tasknotes.dev/features/recurring-tasks/#completion-tracking).
  - Thanks to @14790897 for reporting
- (#2669) Fixed task cards showing a due or scheduled date that falls today as a plain date, such as "Nov 23", while the days either side read "Yesterday" and "Tomorrow". These dates now read "Today", or "Today at 14:00" with a time, and the full date appears on hover as for other relative dates. ISO dates are unchanged.
  - Thanks to @martin-forge for contributing
- (#2665) Fixed mdbase validation errors on project and occurrence template links by removing an unintended target type restriction from TaskNotes-generated types. Existing generated types are corrected when TaskNotes loads the vault.
  - Thanks to @engarthurcardoso for reporting
- (#2649) The **Next week** shortcut in date menus, Quick Actions, and the date and time picker now follows the **First day of week** setting. If today is that weekday, the shortcut selects the same weekday seven days later.
  - Thanks to @erezbm for reporting
- (#2651) Unskipping an occurrence in the task editor's **Completions** calendar now stays saved, even when it was the last skipped occurrence. Reopening a skipped or completed occurrence also recalculates the dates without marking the task as manually rescheduled.
  - Thanks to @prepare4robots for reporting
- (#2655) Calendar dates that only open a daily note are now plain text when no daily-note provider is enabled. Dates that switch views or select a day in the month panel still work.
  - Thanks to @martin-forge for reporting
- (#2657) Fixed task links that make up a callout title collapsing in Live Preview and Reading View. The task card now fits its title and properties instead of squeezing into a narrow column.
  - Thanks to @EddyCurrrent for reporting
- (#2647) Fixed calendar events with a linked note having a grey outline around their whole row in the Calendar view's list (Agenda) layout and the month view's selected day panel, which made the row look selected. The note icon after the title still marks these events; the outline in the calendar grids is unchanged.
  - Thanks to @martin-forge for contributing
- (#2645) TaskNotes retries temporary settings read errors instead of treating an unreadable file as missing. If the file remains unreadable, TaskNotes stops without overwriting it and logs what failed.
  - Thanks to @chrabia for reporting
- (#2643) Fixed task links in [Note Toolbar](https://github.com/chrisgurney/obsidian-note-toolbar) callout toolbars (`> [!note-toolbar]`) breaking the toolbar layout since 5.0. A task link as a toolbar item turned into a narrow card whose title wrapped over several lines and overlapped the next item. Task links in these toolbars now show the task's status and title on one line, as a task link inside a sentence does.
  - Thanks to @hm-24 for reporting
- (#2641) Fixed tasks in the calendar's Month view not moving when dragged while the calendar is 850px wide or narrower. At that width Month shows tasks as compact chips, and dragging one selected days and opened the create menu instead. The chips can now be dragged to another day, clicked to open the task and right-clicked for the task menu, as in the wider layout. With **Show selected day panel** on, pressing a chip still selects its day.
  - Thanks to @jvvehh-arch for reporting
- (#2635) Fixed task rows in the Calendar view's list (Agenda) layout having rounded corners, which curved the divider under each task up at both ends while the divider under a calendar event ran straight. Task rows now have square corners like event rows; task blocks in the day, week and month grids keep their rounded corners.
  - Thanks to @martin-forge for contributing
- (#2579) Fixed task links in notes taking extra space on phones in Live Preview. A task link on a checkbox line (`- [ ] [[Task]]`) took three lines (checkbox, task, then the convert button) and now stays on one row, level with the checkbox. When no status or priority is shown, the title no longer starts after an empty gap.
  - Thanks to @BrucePlumb for reporting
- (#2602) Fixed the time range shown while dragging to create a timeblock, task or time entry in the calendar being hidden behind existing events. The selection now draws above existing events, so its time range can be read while dragging over them.
  - Thanks to @RumiaKitinari for reporting
- (#2624) Fixed the tops of the Sort, Group, Filter, Properties and Search labels being cut off in the Relationships widget toolbar when the toolbar wrapped onto two lines. The toolbar's header now grows to fit it, in the Relationships widget and in other TaskNotes Bases views.
  - Thanks to @prepare4robots for reporting
- (#2618) Fixed the "About default `.base` files" note at the end of the release notes pointing to a General settings page that no longer exists. It now points to **Settings → TaskNotes → Appearance & interaction → Views & base files → Update files** and mentions the **TaskNotes: Update default base files** command.
  - Thanks to @Alireza-RS for reporting
- (#2606) Fixed Ctrl/Cmd-click on a task in Task List, Kanban, Calendar and Agenda views selecting the task instead of opening its note in a new tab. Ctrl/Cmd-click and middle-click now open the note in a new tab on every task card, calendar event and task link in a note, as links do in Obsidian; Ctrl/Cmd+Alt-click opens it to the side. To select several tasks, Shift-click a task first; while a selection is active, Ctrl/Cmd-click adds or removes tasks as before. The task menu again has **Open note in new tab** next to **Open note**, instead of only under **Note actions**. See [Task List view](https://tasknotes.dev/views/task-list/#task-actions).
  - Thanks to @minchinweb for reporting
