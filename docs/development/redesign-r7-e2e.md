## Product changes and controls

- Calendar rejection cleanup is deferred with the **owner window's timer**, not a microtask: native Chromium can run a microtask checkpoint between event listeners. The new unit regression rechecks rejection during pointerup. Popout coverage uses a real window-backed iframe document. Pointer cancel, Escape, blur, source refresh and disposal still clear previews.
- Parent assignment and subgroup labels reuse existing translation descriptors; no new messages or catalog changes. Shared Undo and existing mutation paths remain in use.
- Calendar status borders and Kanban tints restore documented design-system behavior; they do not modify the vendored calendar engine or AA's layouts.
- Shared keyboard handling retains actual DOM focus through row replacement, rather than just repainting a remembered task. Seven focused unit cases cover status/priority/date identity, pointer focus with native-order focusout, intentional root/external focus, and ambiguous-control fallback. A deterministic pointer/removal test failed before the final fix and passes after it (`focus-pointer-before.log`, `focus-pointer-after.log`). Earlier keyboard-only restoration passed unit tests but still failed native case 29; console instrumentation could mask the race and was removed before acceptance.
- Test setup fixes wait on observable state/input, not sleeps, larger timeouts, mutation retries or skips. Stored statuses/priorities, date/time preservation, cycle prevention, stale Undo guards and task identity remain asserted.
- User-facing fixes and existing contributor acknowledgements are in `docs/releases/unreleased.md`; test-only changes are not listed there.
